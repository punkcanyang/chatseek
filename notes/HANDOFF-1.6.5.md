# Chatseek 1.6.5 交接

版本 **1.6.5**。基準 `6750471`（1.6.4，最後活動時間）。分支 `feat/image-tab`。權限仍恰好是 `["sidePanel"]`。`host_permissions` 與 CSP 沒有改。沒有新的網路請求，不重新抓圖，不存圖片網址。資料庫仍是版本 4。診斷仍不含內文、網址、id。

## 這版做了什麼

側欄在「全部」後面加了「圖片」頁籤。「活躍中」仍是第一個。既有順序是：活躍中、ChatGPT、Claude、Grok、Gemini、已封存、全部、圖片。

格子只畫已經收進 IndexedDB 的圖。縮圖用 `data:` 網址，因為擴充功能頁的 CSP 是 `img-src 'self' data:`，沒有 `blob:`。點縮圖會打開閱讀頁，捲到那一張，並加上約 4 秒的外框。每張縮圖右上角的小圖示沿用 1.5.1 的「一則對話一個分頁」（`FOCUS_ORIGINAL`），沒有加 `tabs` 權限。

預設不顯示未快取、過大、逾時、還沒載完、已清除。勾選「顯示未快取」才出現原因卡。排序用對話的 `updatedAt`（1.6.4 的最後活動時間），新的在前。同一則對話裡依出現順序：訊息在頁面上的順位，然後 offset，然後 index。平台篩選是全部、ChatGPT、Claude、Gemini、Grok。

320px 寬是兩欄。格子只建立看得到的那幾格（上下各多兩列），只有這些格子會解碼。離開視窗就放開網址；若將來出現 `blob:`，`releaseUrl` 會 `revokeObjectURL`。這版的產品路徑不呼叫 `createObjectURL`。

九種語言都有空狀態「還沒有快取的圖」（各語的對應句子）。清除圖片快取後，這個頁籤立刻更新：沒勾選時格子空掉；有勾選時那些卡變成「已清除」。對話文字留著。

圖片頁籤打開時，搜尋框和對話排序列會收起來。這個頁籤不拿搜尋字去掃圖。從格子打開閱讀頁時搜尋字是空的，避免搜尋高亮把捲動搶走。

## 硬規矩

- `permissions` 恰好 `["sidePanel"]`。
- `host_permissions` 與 CSP 與 1.6.4 相同。
- 沒有新的網路請求，不重新抓圖，不把圖片網址寫進資料庫。`listImageCards` 只回中繼資料（平台、標題、對話網址、時間、狀態、位元組數），不複製 blob，也不帶 `url`／`src`。
- 縮圖、格子、閱讀頁定位都不用 `innerHTML`。
- `scripts/verify.mjs` 只加嚴：版本 1.6.5、圖片頁籤在「全部」之後、未快取開關與格子、`listImageCards`／`filterImageCards`、格子檔不得 `innerHTML`／`fetch`／`new Image`、縮圖必須是 `data:image/`、閱讀頁要能帶 `m` 並標 `is-target`、九個語系都有頁籤文案。
- 診斷仍不含內文、網址、id。

## 測試與效能

```bash
npm run verify
npm run test:search
npm run test:fixture
npm run test:upgrade
npm run test:e2e
node scripts/image-grid-bench.mjs
node scripts/reader-bench.mjs /workspace /tmp/chatseek-164
node scripts/list-bench.mjs /workspace /tmp/chatseek-164
```

以上都過。端到端用 Chrome for Testing 155.0.8059.39，`--load-extension`，`--host-resolver-rules` 把 `chatgpt.com:443` 與 `files.oaiusercontent.com:443` 指到本機 HTTPS。沒有加 `host_permissions`。

圖片頁籤在既有的圖片案例之後：320×720 打開「圖片」，縮圖的 `src` 都是 `data:image/`，格子文字沒有 `http` 或 `oaiusercontent`。勾選顯示未快取後出現原因卡。去原網站圖示交出的網址是對話站（ChatGPT／Claude／Grok／Gemini），不是圖片網址。縮圖交出的閱讀頁網址帶 `m` 和 `i`，既有閱讀頁載入後捲到那張並出現 `.is-target`。這兩下在測試裡先記下 `chrome.tabs.create` 的網址再還原，避免另開分頁把偵錯連線卡住；產品本身仍是 `FOCUS_ORIGINAL`／`FOCUS_READER`，沒有對上就 `chrome.tabs.create`。單元測試覆蓋真正的 `openChat` 網址，以及 `m`／`i` 變了會重載同一則閱讀頁。

複審把縮圖位元組從清單列拆到 meta。`readImagesForMessages` 仍只為閱讀頁要畫的訊息把位元組接回去。已封存對話的圖留在格子裡。

500 張已快取縮圖（96×64 webp），同一台機器跑 3 次取中位數：開啟 40ms，捲動 p50 1.1ms，p95 1.6ms，最大 1.9ms，畫面上 16 格。位元組已不在清單列上，這次開啟含第一次把舊列拆開的檢查；清單本身只掃中繼資料。

3000 則、沒有圖片的閱讀頁，各跑 3 次取中位數，對照 `6750471`。複審這台機器：

## 老闆實測

1. 到 `chrome://extensions` 重新載入，確認版本 1.6.5，權限只有側邊欄。已經開著的對話分頁重新整理。不該出現新的權限提示。
2. 打開一則已經有快取圖的對話。側欄「活躍中」仍在最前，「圖片」在「全部」後面。把側欄拉到大約 320px，縮圖是兩欄。不該為了這個頁籤重新抓圖。
3. 點一張縮圖：閱讀頁打開，捲到那張，外框亮一下。右上角的小圖示回到同一則對話的分頁。
4. 勾選「顯示未快取」：原因卡會寫原網站限制、檔案過大、轉檔逾時、圖還沒載完，或已清除。
5. 按「清除圖片快取」。沒勾選時格子空掉；有勾選時那些卡變成已清除。對話文字還在。

## 已知限制

- 縮圖是 `data:` 網址。CSP 沒有 `blob:`。離開視窗會丟掉這個字串；若出現 `blob:` 才會撤銷。
- 圖片頁籤不搜尋圖裡的字。搜尋框和對話排序在這個頁籤收起來。順序固定是最後活動時間，然後同一則裡的出現順序。
- 已封存對話的圖也會出現。
- 從格子打開閱讀頁時不帶側欄的搜尋字。
- 高亮大約 4 秒後拿掉。
- 清單列不再帶縮圖位元組。位元組放在既有的 meta 表（`imgb:`），資料庫仍是版本 4。1.6.0–1.6.4 已寫在同一列上的圖，第一次打開圖片頁籤時每次搬 32 張，之後清單只讀中繼資料。看得到的格子才讀位元組。
- 已封存對話的圖仍會出現。開工卡要的是已快取的縮圖，這個頁籤排在「全部」後面，而「全部」本來就包含封存。
- 快取更新時，還停在圖片頁籤就保留捲動位置，同一格不重複解碼。離開頁籤會清掉 `data:` 並作廢進行中的載入。側欄寬度變了會重算欄寬。
- 閱讀頁網址的 `m` 是訊息 id，用來捲動，不是圖片網址。圖片列仍會清掉 `url`／`src`／`href`／`currentSrc`，以及 alt／prompt 裡的圖片位址。
- 相對時間、診斷、資料庫版本 4 與 1.6.4 相同。
