# Chatseek 1.6.0 交接

閱讀頁可以留下你打開過的對話裡、頁面上已經載好的圖。版本 **1.6.0**。權限仍只有 `sidePanel`，沒有 `unlimitedStorage`，`host_permissions` 沒有加大。不發新的網路請求，CSP 沒改。資料庫從版本 3 升到版本 4，舊的對話和訊息會留著。

只在那段對話開著、而且 `<img>` 已經畫出來時才存。長邊縮到 512 的 WebP（不行就 JPEG），每張大約 150KB，再大就降畫質，還是太大就不存這張。同時記下提示詞、alt、屬於哪一則訊息、第幾張。不存圖片網址。

跨網域或 canvas 被污染時，只留提示詞和 alt。閱讀頁原位顯示「圖片未快取（原網站限制）」。降畫質之後仍超過約 150KB 的圖也留下提示詞和 alt，原位顯示「圖片未快取（檔案過大）」。這兩句都有九種語言。點縮圖或佔位，跟「前往原網站開啟」一樣，同一段對話只留一個分頁。

側欄底部有圖片快取佔用的空間，和「清除圖片快取」（會先問一次）。從索引移除對話時，圖會一起刪。

- `docs/reader-1.6.0-placeholder.png`：同一則裡兩種佔位，「原網站限制」和「檔案過大」，都附「前往原網站開啟」。
- `docs/panel-1.6.0-image-cache.png`：側欄底部的「圖片快取 3.7 KB」和「清除圖片快取」。

## 四家的圖片怎麼找

都只看已經收進訊息的那個節點，不看側欄、不看網址列上的頭像。小於 64px、class 像 avatar / icon / logo 的圖會略過。

| 平台 | 選擇器 | 預估能不能快取 |
| --- | --- | --- |
| ChatGPT | 訊息節點裡的 `img`（含 `[data-message-author-role]`、`[data-turn]` 裡的圖） | 部分。同一網域或頁面自己產生的 blob 有機會；`oaiusercontent.com` 這類跨網域多半被污染，改顯示佔位 |
| Claude | 使用者訊息 `[data-testid="user-message"]` 裡的 `img`，以及它前面最多三個兄弟節點裡的上傳圖。不讀 artifact iframe，也不收 `.artifact` | 部分。使用者上傳、且頁面已畫出來的圖有機會；artifact 裡的圖不碰 |
| Gemini | `user-query` / `model-response` 裡的 `img`，含 `generated-image img`、`single-image img`，以及這個訊息裡打開的 shadow root | 部分。`googleusercontent.com` 多半跨網域，會變成佔位；同一頁已經畫好、且沒被污染的圖才存得到 |
| Grok | 訊息節點裡的 `img`，含 `figure img` | 部分。`assets.grok.com` 這類跨網域多半只能佔位 |

這張表的「能不能快取」是依網域和 canvas 規則估的，不是登入後點過的結果。實機請填下面那張。

## 請你在自己的 Chrome 裡看

1. 打開 `chrome://extensions`，重新載入 Chatseek，確認版本是 **1.6.0**。已經開著的 ChatGPT、Claude、Grok、Gemini 分頁各重新整理一次。不要清掉本機索引。權限說明裡不該多出項目，也不該出現「不限儲存空間」。
2. 打開一段你看過、裡面有圖的對話，等圖出現在頁面上。回到側欄，底部應出現「圖片快取」和一個大於 0 的大小（若那張圖是跨網域、存不了，大小可能仍是 0，閱讀頁會是佔位）。
3. 點該列的閱讀。圖的位置應有縮圖，或是「圖片未快取（原網站限制）」加上「前往原網站開啟」。不該去請求原本的圖片網址。
4. 點縮圖，或點佔位上的「前往原網站開啟」。應切回已經開著的那個網站分頁；關掉之後再點，才會新開。Gemini 網址裡的 `/u/數字/` 應還在。
5. 側欄點「清除圖片快取」後先取消，大小不該變。再點一次並確認，大小應回到 0 B，對話列表還在。閱讀頁重新整理後，縮圖應變成佔位或消失（沒再打開網站上的那段之前，不會自己抓回來）。
6. 再打開那段有圖的對話，等快取大小回來。點該列的圓形叉，確認從索引移除。閱讀頁重新整理應寫這段已經不在本機索引；快取大小應少掉那些圖。
7. 把側欄語言改成 English 或繁體中文，佔位那句和「清除圖片快取」應跟著變。
8. 打開一段很長的對話上下捲，頁面應還能捲，不該一次把幾千則都畫出來。

## 做不到的

- 沒有 `crossOrigin`、也沒有重新抓圖時，跨網域的圖畫進 canvas 會被污染。這種圖只能佔位，不能變成縮圖。要能存，就得加權限或重新請求，這版故意不做。
- 不存圖片網址，所以點縮圖是回到那段對話，不是打開圖片檔。
- 你還沒把那段對話開到圖出現就離開的話，那張圖不會進快取。
- Claude 的 artifact iframe 不讀。
- 頭像和小於 64px 的介面圖不收。
- 沒有 `unlimitedStorage`。磁碟配額不夠時，那張圖會存失敗，對話文字還在，已存的縮圖和使用量不會被寫壞。
- 降畫質之後仍超過約 150KB 的圖不存像素，閱讀頁改顯示「檔案過大」佔位，和「原網站限制」是兩句不同的話。

## 自動化

```bash
npm run verify
npm run test:search
npm run test:fixture
npm run test:gemini
npm run test:upgrade
```

`scripts/image-cache-test.mjs`（含在 `test:search` 和 `test:upgrade`）：canvas 被污染、`SecurityError` 或其他轉檔錯誤時只存提示詞和 alt；`toBlob` 一直不回呼也不會卡住；超過 150KB 改存「檔案過大」佔位。清除圖片快取會留下對話和 tombstone，移除對話時連圖一起刪，版本 3 的資料庫升級後訊息和 tombstone 還在且出現 `images` store。配額不足時這張圖存失敗，對話和使用量維持原狀。另外用假的 DOM 檢查四家：ChatGPT 留下生成圖、略過頭像、按鈕圖示和重複來源，順序照文件；Claude 使用者上傳含泡泡前的那一列，不收上一則、不收助理、不收 artifact；Gemini 讀得到打開的 shadow root；Grok 留下訊息裡的大圖。閱讀頁的縮圖是 `data:` 網址，兩種佔位是繁體那兩句，和 Markdown 的圖片文字不重複，點了開的是對話網址。

示例截圖用 `node scripts/screenshot-images.mjs` 重做。它用本機 Chrome 打開擴充功能頁面，寫入假索引和一張 canvas 畫的圖，不登入任何網站。
