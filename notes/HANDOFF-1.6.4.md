# Chatseek 1.6.4 交接

版本 **1.6.4**。基準 `186d952`（1.6.3）。分支 `fix/last-activity`。權限仍恰好是 `["sidePanel"]`。`host_permissions` 與 CSP 沒有改。沒有新的網路請求，不重新抓圖，資料庫仍是版本 4。

## 根因

老闆在 1.6.3 看到的是：圖有進來，但對話有新訊息之後，最後活動時間不往前走。程式對得上，不是推測。欄位是對話列上的 `updatedAt` 加 `updatedAtSource`，沒有另一欄叫 lastActivity。

### 新訊息沒有被判成「剛剛」

1.6.3 的 `sawNewTail` 要同時成立才會蓋上 `observed`：

- 這則對話已經有收錄則數（`baselineCount > 0`）。第一次收錄不是「剛剛」。
- 已存的 `tailMessageId` 必須出現在這次的 `pageMessageIds` 裡。
- 頁尾 id 和它不同，或同一個 id 的正文變了。

1.6.1／1.6.2 的擷取在沒有 `data-message-id` 時，用 `hash(角色 + 正文前 180 字)` 當 id。DOM→Markdown、文字密度備援、同源 iframe、開放／封閉 shadow、子頁框，只要正文的前 180 字或走的路徑和上次不一樣，舊的尾 id 就不在新清單裡。`sawNewTail` 直接是 false。

新 id 的正文仍會入庫（`changed > 0`），所以圖和文字都在，時鐘卻留在舊的 `page-exact`、`page-bucket` 或 `first-seen`。下一次再開，`tailMessageId` 已經被改成新的頁尾 id（因為有寫入正文），之後每次都以為結尾沒變，時間就一直停著。

### 低信心規則沒有擋住「已經觀察到的新訊息」

`src/activity-time.js` 的順位沒有改：`page-exact` 50、`observed` 40、`page-bucket` 30、`sidebar-rank` 20、`first-seen`／`legacy` 10。`page-exact` 和 `observed` 是同一高信心層，較新的時間勝出。較舊的 `page-exact` 不能把時鐘拉回去。`page-bucket`（例如「今天」）順位更低，也不能蓋掉 `observed`。

1.6.3 失敗是因為新結尾根本沒有被標成 `observed`，不是因為低信心把一個已經標好的新時間蓋掉。這次「看到新結尾」本身就是高信心，時間用現在，而且只會往前。

### 半截擷取把時間也跳過了

時間更新原先寫在 `if (changed)` 裡面。一則較短的前綴（`poorerBody`）或「頁面則數變少、新 id 的正文是已存正文的前綴」會略過每一列，`changed` 是 0，時鐘也不寫。

這次改成看頁尾正文對上已存的尾文，活動成立就蓋 `observed`，即使這一批沒有覆寫正文。同一則變短、往上捲出較舊的訊息、第一次收錄、只打開同一個結尾，都不是活動。訊息數變多本身也不夠：往上捲也會讓則數增加，但頁尾沒變。

同一輪擷取若分成多段（一段最多 20 則），前段可能還沒帶到頁尾。`captureSawTail` 記在這輪的對話列上，等帶著頁尾的那一段再決定。id 被重算時，用正文對上已存的尾文，不要求舊 id 還在。

### 側欄和閱讀頁

寫入後 `INDEX_UPDATED` 本來就會讓側欄重新查、依「最近更新」重排。`page-exact` 和 `observed` 同屬第一層，較新的在上。

「N 分鐘前」以前只在畫列表時算一次，時間過了也不改字，除非整表重抓。側欄現在在分頁可見時，以及每 15 秒，只改已經畫出的時間文字，不重讀資料庫，也不重排（順序跟時間戳，不跟這句話）。閱讀頁改聽 `INDEX_UPDATED`，只讀對話列（`readConversationRow`），標頭時間跟側欄用同一套標籤。不重掛訊息，所以 3000 則的視窗不會為了時鐘再畫一次。

四家都走 `writeMessages` 這一條。ChatGPT、Claude、Gemini、Grok 的單元測試都覆蓋了。

## 這版改了什麼

權限仍恰好是 `["sidePanel"]`。`host_permissions` 與 CSP 沒有改。沒有新的網路請求，不重新抓圖，不用 `innerHTML`。資料庫仍是版本 4。診斷仍不含內文、網址、id。

- 新結尾（頁尾換了一則，或同一則正文變長）標成 `observed`，時間是現在，而且不能比已存的高信心時間更舊。
- id 被重算時，用尾文對上，不要求舊 id 還在。Markdown 記號（`*_`#[]()>`~`）和空白不拿來當「換了一則」。
- 同一則因 id 重算不會再存第二列。對的是角色、正規化正文，再加上它在頁面順序裡的位置。真的連送兩次的同文位置不同，兩列都留著。圖跟著留下的那一列。
- 只打開同一則、往上捲、結尾變短、第一次收錄，都不改成「剛剛」。串流仍是 800 毫秒防抖後才寫，不是每個 token 一筆。
- 側欄的相對時間會自己往前走。側欄或閱讀頁不可見時，15 秒計時器會清掉。閱讀頁標頭跟側欄一致，而且不重讀訊息。


以上都過。`scripts/verify.mjs` 只加嚴：版本 1.6.4、順位字串照舊、較新的 `observed` 必須蓋過較舊的 `page-exact`、較舊的 `page-exact` 不得倒退、重算 id 的新結尾算活動、同一個結尾和往上捲不算、`db.js` 要呼叫 `pageShowsNewActivity`、側欄要重畫相對時間、閱讀頁要聽 `INDEX_UPDATED` 並只讀對話列。

`scripts/activity-test.mjs` 對 ChatGPT、Claude、Gemini、Grok 各做：第一次收錄不是 `observed`、再開同一則時間不變、穩定 id 的新訊息變成「剛剛」且往前、只重算 id 而結尾相同不變、同一輪把 id 重算並加上新結尾會更新、結尾變長會更新、往上捲不變、較短前綴不變、之後再寫入較舊的 `page-exact` 或 `page-bucket` 不會倒退。另有一次 22 則分段：前 20 則重算 id 時不蓋時間，帶著新頁尾的下一段才蓋，而且整段加新結尾之後是 23 列，不是兩份。同一則重算 id（含串流把 id 換掉、正文變長）不會多一列；中間夾著別句的兩次「ok」會留著；整段複本在畫面上只剩一份時會收成一份，兩份都看得到就留著。空查詢依最近更新排序時，剛更新的那則在未更新的那則前面。

端到端用 Chrome for Testing 155.0.8059.39，`--load-extension`，`--host-resolver-rules` 把 `chatgpt.com:443` 指到本機 HTTPS。沒有加 `host_permissions`。在既有的圖片案例之後：

- 經典選擇器：同一輪拿掉 `data-message-id` 並加上一則新訊息。IndexedDB 的 `updatedAtSource` 變成 `observed`，時間比打開時晚，則數增加。只重新打開、沒有新訊息時，時間和來源都不變。
- 文字密度備援（Heuristic habitat）、同源 iframe、開放 shadow：各在對話中途加一則，同樣變成 `observed` 且時間往前。只打開不更新。

- 側欄改成繁體後，最上面是「open shadow habitat」，時間「剛剛」。封閉 shadow 那一列不是「剛剛」。閱讀頁標頭也是「剛剛」，正文含剛加上的那一則。

## 老闆實測

1. 到 `chrome://extensions` 重新載入，確認版本 1.6.4，權限只有側邊欄。已經開著的對話分頁重新整理。不該出現新的權限提示。
2. 打開一則已經收錄、沒有新訊息的舊對話。側欄時間不得變成「剛剛」。
3. 在那則裡送出一則新訊息。它要跳到「最近更新」最上面，時間是「剛剛」。打開閱讀頁，標頭要同一句。
4. Claude、Gemini、Grok 各做一次第 2 步和第 3 步。過一分鐘後，字可以變成「N 分鐘前」，順序仍跟時間戳。不該為了這件事重新抓圖，也不該多出新的網路請求。

## 已知限制

- 上一則的用詞真的改了（不是 Markdown 記號或空白），而且 id 也一起換掉、頁面上又對不到原來的尾文時，這次不會把它當成新結尾。穩定的上一則上面再加一則新訊息，仍然會往前走。
- 畫面上的視窗沒有包含已存的頁尾時，不會變成「剛剛」。這是故意的，避免半截畫面把舊對話標成現在。
- 則數變多本身不是活動。往上捲出較舊的訊息不會更新時間。只有更晚的頁尾，或同一則正文變長，才會。
- 用詞真的改了（正規化之後對不上），而且 id 也換了、頁面上又對不到原來那一則時，仍可能多存一列。把它併進舊列會蓋掉原來的正文。
- 已經整段被原樣存成兩份以上、而且這次畫面只看到其中一份（至少兩則）時，多出來的那幾份會收掉。畫面同時看得到每一份，就不動。只重複一句、中間還有別的訊息，不會被當成整段複本。
- 封閉 shadow 無法從頁面世界在端到端裡追加節點；開放 shadow 測了追加。跨源 iframe 仍然讀不到，沒有加 host 權限。
- 相對時間在側欄或閱讀頁可見時每 15 秒改字，不可見就清掉計時器。它不自己重排；順序是時間戳。
- `background.js` 仍會丟掉超過 300 字的 `pageMessageIds` 項目。這次沒有改。一般的 ChatGPT id 遠短於這個上限。
- 診斷不含內文、網址、id。沒有新的權限、host 或 CSP。資料庫仍是版本 4。
