# 交给老板：Chatseek 1.1.0 自己电脑上怎么验

分支 `fix/chatgpt-capture-dates`，版本 **1.1.0**。本环境不能登录 ChatGPT，没有代开你的账号。自动化 `npm run verify` 和 `npm run test:search` 过了；下面这几步要你在自己的 Chrome 上勾。

## 先看的结论

ChatGPT「只有标题、搜不到正文」在代码里能对上的机制是：三个旧选择器都落空时，消息数就是 0，扩展照样把标题写进库，控制台什么都不说。10 月初的页面如果改成 `data-turn` / `data-message-id`，或者整页包在 `<form>` 里，就会走这条路。没登录真实页面，不能把「就是这个 DOM」说死；这一版把这几种结构都补上了，并且 0 则消息时会出提示，方便你把真实 DOM 截回来。

另一种同样说得通、也还没在你机器上排除的情况：扩展更新之后，已经开着的 ChatGPT 标签没刷新，内容脚本根本没进去。所以第一步是重新整理那些标签。

## 在你自己的 Chrome 上

1. `chrome://extensions` → 找到 Chatseek → **重新加载**。版本应是 **1.1.0**。网站访问权限是「在所有网站上」，或至少包含 chatgpt.com。图标应是深色圆角方块上的绿色符文（方向 D）。
2. **重新整理**所有已经开着的 ChatGPT 标签。只点扩展的重新加载，不会给旧标签换上新脚本。
3. 开一个**新对话**，发出一句独特的话，例如 `zebrafox1008`，等回复结束、地址变成 `/c/...`。
4. 打开 Chatseek 侧栏：
   - 最上面能看到这条对话。
   - 搜索 `zebrafox1008` 能命中正文，不只是标题。
   - 底部有一行「ChatGPT：最后收录 …，N 则消息」，N 至少是 2。
   - 时间是刚才的活动时间，前面**没有**「約」。
5. 再打开几条你没在 Chatseek 里续写过的旧对话（今天、上周、更早各一条，在 ChatGPT 侧栏里从上往下点开）。没有页面精确时间时：
   - 顺序应跟 ChatGPT 侧栏最近活动一致，而不是你点开它们的顺序。
   - 推出来的时间前面有 **「約」**，鼠标停上去会写「推估：依側欄順序」。
   - 侧栏里完全没有可参照的时间时，显示 **「日期未知（收錄於 …）」**，不要整栏都是「刚刚」。
6. 在一条旧对话里再发一句新的。它应跳到 Chatseek 最上面，时间变成刚刚，且**不加**「約」。刷新页面、重新加载扩展之后，这个顺序还在。
7. 健康检查：正常对话页底部不应出现「页面可能改版」，工具栏角标也不该是 `!`。若某条 `/c/` 页确实 0 则消息，侧栏底部会出现「ChatGPT 页面可能改版，请回报」，角标为 `!`。这时打开该页的开发者工具 Console，应有一行 `[Chatseek] chatgpt: 0 messages on /c/ page, selectors tried: …`，里面没有对话正文。把这一行和该消息元素的 HTML（文字打码）发回来即可。
8. 临时聊天（地址带 `temporary-chat=true`）不应进库。Claude、Grok 各打开一条旧对话再搜一句正文；底部应有对应平台的「最后收录」行。
9. 长对话要先往上滚到旧段落出现在页面上，再搜那段里的词。没画出来的历史仍然收不到。

## 已知限制

- 不读网络、不代持 Key、不加 `scripting` 权限，所以更新后必须自己刷新已经打开的网站标签。
- 置顶对话如果页面上没有「Pinned / 置頂」这类标题，插值可能把它算进普通顺序。
- 升级前已经收进库、又分不清是不是采集时间的旧记录，会在你再次打开该站侧栏时重估。重估之前，侧栏可能显示「日期未知」。
- 这一版没有做 Gemini。Gemini 分支 rebase 之后直接用 `notes/CHANGELOG-1.1.0.md` 末节的共用入口。
