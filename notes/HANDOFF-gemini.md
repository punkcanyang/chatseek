# 交給複審 / 老闆：Chatseek 1.2.0 Gemini

分支 `feat/gemini`，請先複審，不要直接合進 main。開發機沒有登入任何 Google 帳號。費用 $0，沒有呼叫付費服務。

這版接在已經合進 main 的 1.1.0（`724dbd7`，共用最後活動時間和收錄健康檢查）上面。Gemini 只登記自己的網站、側欄順序和健康檢查，不再自備 `exact` / `estimated` / `unknown`。

## 改了什麼

- 第四家：gemini.google.com。側欄清單、目前這則對話的訊息、搜尋、只篩 Gemini。
- 只讀頁面上已經畫出來的內容。沒有 fetch / XHR，沒有 API Key，沒有打 Gemini 內部介面。
- 權限只加 `https://gemini.google.com/*`。www.google.com、aistudio、bard、mail、accounts，以及 Perplexity、DeepSeek，驗證腳本仍會拒絕。
- 多帳號網址保留 `/u/N/`。這則頁面自己的路徑優先（所以 `/u/4/gem/...` 不會被改成預設帳號）。側欄連結如果沒寫帳號，就沿用目前這個分頁的 `/u/N/`。兩邊都沒有時，存成 `/app/<id>`，點回去可能開到預設帳號。
- `/share/`、沒有 id 的 `/app`、Gem 編輯頁不收。
- 圖示仍是 1.1.0 的方向 D（深色圓角底上的符文）。這版沒有換標。
- 日期跟 ChatGPT / Claude / Grok 同一套，文案在 `src/activity-time.js`：
  - 這一列有 `time[datetime]` 或時間屬性：`page-exact`，畫面上是普通的最後活動時間，不加「約」。
  - 沒有精確時間，但側欄裡至少有一則已經有精確時間或分組時間：按上新下舊插值，來源是 `sidebar-rank`。繁體顯示「約」，簡體顯示「约」。
  - 整欄都沒有那種錨點：來源留在 `first-seen`。繁體是「日期未知（收錄於 …）」，簡體是「日期未知（收录于 …）」。括號是收進索引的時間，不是活動時間。排序仍跟側欄，越上面越新，但不會把每一則都標成「約」，也不會整欄顯示「剛剛」。
- 比較準的時間不會被比較鬆的蓋掉。
- 打開的對話頁如果一則訊息都沒讀到，大約 8 秒後仍是 0，側欄底部會提示，工具欄角標是 `!`。繁體像是「Gemini 頁面可能改版，請回報（最後收錄 hh:mm，0 則訊息）」。有讀到訊息時，底部是「Gemini：最後收錄 hh:mm，N 則訊息」。控制台只打選擇器名字，不打正文。沒有 id 的頁面、分享頁，不會被當成這次失敗。

## 怎麼測（自動化）

在倉庫目錄：

```bash
npm run verify
npm run test:search
npm run test:fixture
npm run test:gemini
```

`test:search` 含 IndexedDB 1 → 2 的升級測試。`test:fixture` 是 ChatGPT。`test:gemini` 用離線 HTML，不登入。它檢查：使用者 / Gemini 角色和順序、思考過程、「You said / 你說了 / Gemini 說了」、按鈕、輸入框都沒被收進去，分享頁和沒有 id 的 `/app` 會被跳過，以及日期是接到共用的 `page-exact` / `sidebar-rank` / `first-seen`，不是 Gemini 自己估的時間。

## 老闆在自己電腦上怎麼測

開發機不能登入 Google。請在自己的 Chrome、自己的帳號上做。不用另外付費。

1. 拿到這個分支的資料夾。打開 `chrome://extensions`，打開開發者模式。
2. 如果已經裝過 Chatseek，點「重新載入」。沒裝過就點「載入未封裝項目」，選這個資料夾。版本應是 **1.2.0**。工具欄圖示是方向 D 的符文，不是舊標。
3. 把已經開著的 gemini.google.com 分頁重新整理一次。擴充重新載入不會自動換掉舊分頁裡的腳本。ChatGPT / Claude / Grok 的分頁也要重新整理一次，才會用 1.1.0 之後的內容腳本。
4. 在 Gemini 打開至少 3 段舊對話（點進每一段，讓正文畫出來）。臨時對話、或關掉活動記錄所以網址沒有 id 的，本來就不會收。
5. 打開 Chatseek 側欄，搜其中一段裡很少見的詞。應該命中那一段，標籤是 Gemini。點那一列，應開回原來的對話（多帳號的話，網址裡最好還看得到 `/u/N/`）。
6. 搜一個顯然不存在的詞，應顯示沒有符合。
7. 關掉側欄再打開，或到擴充頁面重新載入擴充再開側欄。剛才的索引還在。網站分頁要再重新整理，才會繼續收新內容。
8. 日期不該整欄空白，也不該三段都是「剛剛」。Gemini 側欄通常沒有時間，所以多數會是「日期未知（收錄於 …）」（簡體介面是「日期未知（收录于 …）」），順序仍大致跟 Gemini 側欄一樣，越上面越新。只有某一則旁邊真的有時間（或分組）時，旁邊那幾則才顯示「約」／「约」。不要期待每一則 Gemini 都有「約」。
9. 篩選按「Gemini」只剩 Gemini；按「全部」會跟 ChatGPT、Claude、Grok 混在一起。
10. 如果某段網址是 `/app/<id>`（或 `/gem/.../<id>`）的對話，正文明明在畫面上，等大約 8–10 秒仍搜不到正文：側欄底部要出現 Gemini 的改版提示，工具欄角標是 `!`。瀏覽器主控台那一行只有選擇器名字和「0 messages」，沒有對話正文。沒有 id 的新對話不該觸發這個提示。

測完請截圖。

## 已知限制

- 沒在這個分頁打開、也沒出現在側欄裡的舊對話，仍然搜不到。這次不做「一次收完全部歷史」，也不匯入 Google Takeout。
- 很長的對話只索引已經畫出來的訊息。要多收，就在那則對話裡往上捲。
- Gemini 側欄多半沒有真實修改時間。沒有錨點時畫面上是「日期未知」，不是「約」。這是 1.1.0 的共用規則，不是 Gemini 壞掉。
- 假設側欄是上新下舊。如果 Gemini 改成別的排序，估計和未知日期的排序會跟著錯，但不會假裝那是精確時間。
- 沒有 `/u/N/` 的網址，點回去可能開到預設帳號。
- 不收 `/share/`、不收沒有 id 的新對話、不收 Gem 編輯頁。Canvas / 圖片沒有另外做；訊息裡的文字如果在正文節點裡，會順便收。
- 選擇器是依公開的開源專案寫的，開發時沒看過登入後的真頁面。第一次實機如果收不到，優先檢查下面幾項。
- 地區要能打開 gemini.google.com，這跟擴充無關。

## 最可能壞掉的選擇器

1. 側欄列：`[data-test-id="conversation"]`，對話 id 在 `jslog` 的 `c_<id>`。其次才是 `a[href*="/app/"]`。
2. 網址形狀：`/app/<id>`、`/u/N/app/<id>`、`/gem/<gemId>/<id>`。id 目前要求 8 到 128 個英數、底線或減號。
3. 使用者訊息：`user-query`、`.user-query`、`.query-text`。
4. Gemini 回覆：`model-response`、`message-content`、`.markdown`、`.model-response-text`。
5. 要排除的思考過程：`model-thoughts`、`.thoughts-container`。
6. 螢幕閱讀器標籤：`.cdk-visually-hidden`（You said、你說了、Gemini 說了）。
7. 輸入框：`.ql-editor`。

找不到時會安靜跳過，不會對頁面報錯。0 則訊息的對話頁會走上面的健康檢查。
