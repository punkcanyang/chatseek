# Chatseek 1.4.0（2026-10-08）

封存的对话还在索引里、还能搜；页签按「活跃 → 四家 → 已封存 → 全部」排；界面改成 Chrome 标准的 `_locales`，侧栏可以手动换语言。仍然只读页面，不发网络请求，不碰 Gemini 的 `batchexecute`。

## 封存

- 被标成已封存的对话**留在索引里**，搜索和「已封存」页签都能看到，标题旁有灰色「已封存」。
- 只有页面上**明确写出**这段已封存时才标。从网站侧栏消失不改状态，也不会自动删除。
- 之后又在未封存的上下文里看到同一段（ChatGPT 网站侧栏的对话列表，或打开的对话页上有输入框、没有封存横幅、也不在封存列表里），恢复成活跃，灰标签消失。
- 对话记录上多三个字段：`archived`、`archiveSource`、`archivedAt`。来源记下是哪一种页面证据，时间是第一次标上（或来源变了）的时刻。
- IndexedDB 从版本 2 升到 3，给 `tokenMap.conversationId` 加了索引（移除单条时不必扫整张倒排表）。`archived` 是对话上的普通字段，在游标里过滤（布尔值不能当 IndexedDB 键，1.3.0 的旧行也没有这个字段）。1.3.0 已有的对话、消息、倒排、预览和健康记录都保留。旧行没有 `archived` 字段，当成未封存。

### 各家怎么判断

| 平台 | 会不会标已封存 | 读的是什么 |
| --- | --- | --- |
| ChatGPT | 会 | 见下方两条。网站侧栏（`nav` / `aside` 里、不在对话框和消息里）的 `/c/` 链接记为未封存（`chatgpt:sidebar`）。打开的 `/c/` 页有输入框、没有横幅、也不在封存列表里，记为未封存（`chatgpt:conversation`）。消息正文里的 `/c/` 链接、认不出的对话框里的链接、或既没有横幅也没有输入框的对话页，只收录，不改封存状态。 |
| Claude | 不会 | 普通对话没有封存横幅，也没有「已封存对话」列表。项目封存是另一种对象。侧栏只提供删除，不能据此猜测。 |
| Grok | 不会 | 历史列表就是普通列表，没有封存横幅或封存页。 |
| Gemini | 不会 | 没有官方的封存横幅或封存页。不从侧栏消失去推断。 |

ChatGPT 只认只读 DOM，两种证据：

1. **封存列表**（`chatgpt:archive-list`）。`[data-testid=archived-chats]` 或 `[data-testid=archived-conversations]`，或者 `role=dialog` / `role=region` 的 `aria-label` 或标题（`h1`–`h4`、`role=heading`）等于一组固定说法（Archived chats、已封存的聊天、已归档的聊天、アーカイブしたチャット等，后面只允许跟一个数量）。标题在消息正文里、或区域里含有消息的，不算。这个区域内的 `/c/` 链接标为已封存，并且不写进普通侧栏。
2. **打开对话后的横幅**（`chatgpt:banner`）。对话页上、导航、菜单、对话框和消息正文之外，一段不超过 320 字的 `role=status` / `role=note`、带 archive/banner 的 `data-testid`、按钮或链接。正文包含「this conversation is archived」「此對話已封存」「この会話はアーカイブ」等固定说法，或者按钮／链接的**整段文字**正好是 Unarchive、取消封存、アーカイブ解除、desarchivar 等。菜单里的「封存」不算。消息正文里出现「archived」也不算。

同一批收录里，如果一段对话既在普通侧栏又出现在封存列表，以侧栏为准，保持未封存。

措辞或 DOM 对不上这张表时，这一家就**不标**。不会因为侧栏少了一行就改成已封存。

## 从索引移除

每一行有「从索引移除」。确认后只删本机这一条：对话记录、它的消息、倒排索引里指向它的词条。不向网页发消息，网站上的聊天还在。确认框写明这一点。

移除时在 `meta` 里留一条 `removed:<id>` 记号。之后网站侧栏或封存列表重新扫描，不会把它加回来。在网站上再打开这一段、页面上有消息时，会按当时的页面重新收录，并清掉记号（这是预期行为）。「清除本地索引」会连记号一起清掉。

「清除本地索引」仍是清掉全部，仍用浏览器自己的确认框。

## 页签

从左到右，打开侧栏时停在第一项：

1. **活跃中**：四家里未封存的。
2. **ChatGPT / Claude / Grok / Gemini**：只看这一家，且未封存。
3. **已封存**：四家已封存的（目前实际只会有 ChatGPT，除非索引里有人手工写入）。
4. **全部**：未封存和已封存都在。

搜索框只在当前页签的范围内搜。

## 语言

- `manifest.json` 的名称和说明改成 `__MSG_extName__` / `__MSG_extDescription__`，`default_locale` 为 `en`。`chrome://extensions` 上的名字跟随浏览器语言。
- 文案在 `_locales/`：`zh_TW`、`zh_CN`、`en`、`ja`、`ko`、`es`、`fr`、`de`、`pt_BR`。繁体用台湾用语（「則訊息」「已封存」）。简体用「条消息」「已归档」，悬停说明是「最近一个确切时间」。
- `chrome.i18n` 不能在运行中改语言。侧栏右上角的切换记在侧栏页面自己的 `localStorage`（键 `chatseek.uiLocale`；选「跟随浏览器」时删除这个键）。另一个窗口的侧栏会跟着换。「跟随浏览器」读 `chrome.i18n.getUILanguage()`。面板自己读与 `_locales` 同一份文案（`src/i18n.js`，测试锁住两边一致），不 `fetch` 这些 JSON。
- **没有新增权限**，仍只有 `sidePanel` 和原来的网站权限。
- 日期里的月日和时间用 `Intl.DateTimeFormat` 按当前面板语言排。「约」「早于」「日期未知」以及「刚刚 / N 分钟前」也按该语言写。葡萄牙语（含欧洲葡语标签）用巴西葡语文案。没有对应语言时用英文。

## 没有改的

- 不发网络请求，不拦截 fetch / XHR，不读 API Key，不碰 `batchexecute`。
- 预览、命中高亮、绿色当前对话框、健康检查、Gemini 收录仍按 1.3.0 的方式工作。

## 评审后的修正（合并前）

- ChatGPT「恢复活跃」收紧：只认网站侧栏对话列表里的链接，或打开的对话页上有输入框。消息正文里贴的 `/c/` 链接、认不出语言的封存对话框、还没出现输入框的对话页，都不再把已封存的对话改回活跃。
- 封存横幅不在任何对话框里找；封存列表的标题不能在消息正文里，标题后面只允许跟一个数量。
- 「从索引移除」后，网站侧栏或封存列表重扫不再把它加回来；在网站上打开这一段、页面上有消息时才重新收录。
- 去掉 `storage` 权限，语言选择改记在侧栏页面的 `localStorage`；「跟随浏览器」读 `chrome.i18n.getUILanguage()`；多个窗口的侧栏同步语言。
- 去掉 `conversations.archived` 索引（布尔值不能当 IndexedDB 键，这个索引永远是空的）。
- 文案：日文「索引」改「インデックス」，韩文不用「」，各语言「跟随浏览器」改成自然说法，保存日期的写法按语言调顺。页签加 `role=tab` / `aria-selected`。
