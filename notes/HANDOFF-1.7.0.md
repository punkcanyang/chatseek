# Chatseek 1.7.0 交接

版本 **1.7.0**。基準 `186d952`（1.6.3）。分支 `feat/manual-sync`。權限仍恰好是 `["sidePanel"]`。`host_permissions` 與 CSP 沒有改。沒有加 `tabs`、`alarms`、`storage`。擴充套件自己不發網路請求，不重新抓圖，不用 `innerHTML`。資料庫仍是版本 4。診斷與側欄進度不含對話內文、網址、對話 id。

## 設計

側欄選一家平台，按「開始同步」。Service worker 用 `chrome.tabs.create({ url, active: false })` 開一個背景分頁，之後只用 `chrome.tabs.update` 導航這一個分頁。不呼叫 `tabs.query`，不讀別的分頁的網址或標題。這幾個呼叫不需要 `tabs` 權限；若非加權限不可，這版會停下來寫在這裡，而不是自己加。

待同步清單有兩個來源，都不呼叫網站 API、不捲動、不點網站按鈕：

1. 本機 IndexedDB 裡這家已經收過的對話（依更新時間新的在前）。
2. 同步分頁裡，內容腳本從該網站側欄 DOM 讀到、而且符合這家對話網址形狀的連結。導航前再驗一次 host。查詢字串和 hash 會拿掉。

一開始先打開這家的首頁，讓內容腳本讀已經畫出來的側欄連結。這一步不算進 30 段。接著一段一段打開。頁面上看到訊息之後，要等既有的只讀收錄把這頁寫進 IndexedDB，才算這一段結束，然後才進入下一段的間隔。沒有寫進去就不會換頁。

節奏在 `src/sync-policy.js`，正式常數是：

- 段與段之間隨機 20–40 秒（`SYNC_GAP_MIN_MS` 20000、`SYNC_GAP_MAX_MS` 40000）
- 每批最多 30 段（`SYNC_BATCH_SIZE`）
- 批與批之間休息 10 分鐘（`SYNC_REST_MS` = 600000）
- 連續 3 段 0 則就停（`SYNC_EMPTY_LIMIT`）

測試只能在 service worker 上設定 `globalThis.__CHATSEEK_SYNC_LIMITS`，而且只能把間隔縮短，不能拉長。正式程式不讀 `process.env`。跳過的對話不開頁，也不計入 30 段。最後一段後面不再多等一次間隔。

已收錄、而且側欄時間不比索引新、或側欄條數沒有變多，就跳過。側欄沒有時間也沒有條數時不跳過（只有標題不算「沒有新訊息」）。

停止用網址形狀和 DOM 特徵，不靠內文：驗證碼／Cloudflare challenge、登入頁（密碼欄或登入表單）、錯誤頁、429／rate limit 提示。判斷不了就停。連續 3 段在等完載入之後仍是 0 則也停。收錄超過回報上限（正式 20 秒）還沒寫進索引，也當成看不準而停。停下時同步分頁留著，側欄寫原因。九種語言。

暫停、繼續、停止都在側欄。關掉同步分頁等於停止。瀏覽器重新啟動只會把進行中的同步標成暫停，不會導航。

MV3 的 service worker 會睡著。狀態存在 IndexedDB `meta` 的 `sync:session`（截止時間是時間戳，不靠 `setTimeout` 撐 10 分鐘，也不用 `chrome.alarms`）。側欄開著且看得到時，每 250ms 送一次 tick，用現在時間和存好的截止時間比較。側欄關掉或被蓋住就暫停。不會在背景偷跑，也不會開機自己跑。

## 測試

```bash
npm run verify
npm run test:search
npm run test:e2e-sync
```

`scripts/verify.mjs` 只加嚴：版本必須是 1.7.0；同步相關檔案不得有 `fetch`／XHR／`process.env`／`chrome.alarms`；正式常數必須是 20–40 秒、30 段、10 分鐘；權限仍是 `["sidePanel"]`；同步路徑不得 `tabs.query`、不得讀別的分頁網址、不得 `innerHTML`、不得 `active: true`。

`scripts/sync-test.mjs` 覆蓋網址形狀、跳過、合併佇列、3000 筆合併、啟動不導航、側欄 token 不符就暫停、關分頁即停、連續 3 段 0 則、驗證碼／登入／錯誤／限速／看不準都停且留下分頁、滿 30 段（測試把批大小縮成 2）會休息、看到訊息但還沒入庫會繼續等、等太久就停。3000 筆合併這次 17ms，上限 500ms。

`scripts/e2e-sync.mjs` 用 Chrome for Testing（本機是 155.0.8059.39），`--load-extension`，`--host-resolver-rules` 把 `chatgpt.com:443` 指到本機 HTTPS fixture。間隔用環境變數縮短，正式常數不動。覆蓋：

- 正常同步：兩段都寫進 IndexedDB，使用者那一頁的網址不變
- 側欄時間較舊的已收錄對話不打開
- 暫停期間不再導航，繼續後才開下一段，停止後不再開
- 關掉同步分頁，狀態變成已停止
- 驗證碼頁、登入頁立刻停，分頁留著
- 連續 3 段 0 則停，第 4 段不打開
- 同步分頁 `active === false`，文件沒有焦點

閱讀頁 3000 則這次 8ms，上限 1500ms（`npm run test:search` 裡的 `reader-test`）。沒有退步。

## 老闆實測

第一次只跑大約 5 段。看到驗證碼、登入或錯誤就停，分頁留著，不要讓它繼續。

1. `chrome://extensions` 重新載入，確認版本 1.7.0，權限只有側邊欄。把要測的那一家分頁重新整理。
2. 打開 Chatseek 側欄，選這一家，按「開始同步」。
3. 確認背景多了一個同步分頁，你正在看的分頁沒有被導走，同步分頁沒有跳到前面。
4. 側欄要出現第 N／總數、已收、跳過、失敗。一段和下一段之間會停在「等待中」。按暫停，等超過半分鐘不該再換頁；按繼續才會往下。
5. 關掉同步分頁，側欄要變成已停止。或在跑完大約 5 段後按停止。
6. 若出現驗證碼或登入頁，側欄要寫原因，同步分頁留在那一頁。處理完之後要再同步，先按停止再重新開始。

## 已知限制

- 側欄要開著，下一段才會開始。關掉側欄會暫停。不會在背景、開機或排程裡自己跑。
- 一次只跑一家。暫停時不能直接改跑另一家，要先停止。
- 不捲動、不點網站按鈕、不呼叫網站 API。側欄上還沒畫出來的舊對話不會進這次清單。
- 側欄沒有時間也沒有條數時，無法判斷「沒有新訊息」，這段仍會打開。
- 很長的對話只收畫面上已經出現的訊息。圖片仍沿用 1.6.x：頁面上已經畫出來的才快取，不重新抓。
- 看不準是不是驗證碼、登入、錯誤或限速，或這一頁 20 秒內還沒收錄完，會停，同步分頁留著。
- 佇列最多用 500 條側欄連結、合計 5000 筆。超過的不會在這一次打開。
