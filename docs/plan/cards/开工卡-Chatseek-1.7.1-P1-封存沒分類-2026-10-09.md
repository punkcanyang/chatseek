# Chatseek 1.7.1 P1：ChatGPT 已封存對話沒有分到「已封存」
基準 main e3d42cc（1.7.0），分支 fix/archive-detect，版本 1.7.1。
老闆實測：ChatGPT 已封存（歸檔）的對話沒有分到「已封存」頁籤。（老闆是否打開過歸檔列表或對話頁橫幅，答覆待轉。）

## 先查根因（三個方向都要給證據）
1. 1.4.0 的封存橫幅／歸檔列表選擇器是否在 ChatGPT 現行 DOM 失效（1.6.1 時訊息選擇器在頂層全 0 命中，封存很可能同樣）。
2. 1.6.x 新擷取路徑（文字密度備援／同源 iframe／open+closed shadow）有沒有跑封存偵測。
3. 「恢復活躍」是否太快把封存改回活躍（例如一般擷取／同步分頁／lastActivity 寫入就清掉封存旗標）。

## 要做
- 對話頁封存橫幅偵測要走所有擷取路徑（含 iframe／shadow），選擇器加文字／結構備援（多語系的「已封存／Archived」橫幅與「取消封存」按鈕文字），不點按鈕。
- 歸檔列表（設定→已歸檔對話彈窗）裡的對話連結也要認：彈窗出現時讀取裡面的 /c/<id> 連結標成封存（只讀 DOM）。
- 恢復活躍只能在有明確證據時：該對話頁確認沒有封存橫幅且出現了新訊息，或使用者在擴充裡手動恢復。只是開啟／同步分頁看到、側欄有沒有它，都不算。
- 不得用「從側欄消失」判封存。
- diag 加 `archive=banner:N,list:N`（命中次數，不含內文、標題、id、網址）。
- Claude／Gemini／Grok 的封存行為不回退。
- 1.6.4 lastActivity、1.6.5 圖片頁籤、1.7.0 手動同步行為不回退；同步分頁看到封存橫幅也要標封存。

## 硬規矩
權限恰好 ["sidePanel"]；host_permissions／CSP 不動；不呼叫網站 API、無 fetch／XHR／新網路請求；不點網站按鈕、不改網站 DOM；不重新抓圖；無 innerHTML；verify.mjs 只能加強；診斷不含內文；DB 版本盡量不升（要升要寫遷移與 upgrade 測試）；$0。一定要加權限或網路請求就停下回報。

## 驗收
- 單元＋e2e fixture：ChatGPT 對話頁封存橫幅（頂層、iframe、shadow 三種）、歸檔列表彈窗、封存後再一般擷取／同步／新 lastActivity 不會被改回活躍、手動恢復可改回。
- npm run verify、test:search、test:fixture、test:upgrade、test:e2e、test:e2e-sync 全過；效能對 e3d42cc。
- 範例資料截圖存 docs/（已封存頁籤含 ChatGPT 對話、diag 行含 archive=）。
- 開 PR 到 main，不自己合。回報根因證據、老闆實測 ≤4 步、已知限制。中文。

## 追加（老闆定，2026-10-09 15:47，併進 1.7.1）
1. 原網站已刪除 → 歸到「已封存」：Claude／Grok／Gemini（ChatGPT 打開也找不到時同樣處理）的對話若在原網站被刪除，歸到「已封存」，灰標籤旁加小字「原網站已刪除」（九語）。
   - 只認明確訊號：打開該對話網址時（使用者點開或手動同步），網站顯示「找不到／已刪除／無權限」頁，或被重導回首頁且頁面上沒有這段對話。
   - 登入頁、驗證碼、網路錯誤、限速、還沒載完都不算刪除（同步照 1.7.0 停下）。
   - 不得用「從側欄消失」判定。
   - 之後若能正常打開（有訊息），恢復活躍並拿掉小字。
   - diag 加 deleted=N（命中數，不含內文／id／網址）。
2. 「從索引移除」確認框：文案明講「移除後無法尋回，除非再次打開原對話」；加「不再提示」勾選，存側欄 localStorage；設定裡要能重新打開提示。九語。
驗收補：四家「找不到」頁與重導首頁 fixture、登入頁不誤判、恢復活躍、確認框勾選與設定還原。老闆實測仍 ≤4 步為目標（真的不夠可 5 步，寫明原因）。

## 追加 P0（2026-10-09 15:48，併進 1.7.1）：ChatGPT 生圖進度文字被存成十幾則重複助理訊息
現象：生圖時進度文字（「正在建立圖像25%」「正在勾勒草圖38%」「正在生成初稿51%」「正在打磨細節80%」等）每變一次就多一則助理訊息，閱讀頁出現十幾則幾乎一樣的塊。疑似 1.6.4「同一則正文變長或最後一則換了＝新訊息」＋「角色＋正文＋位置」比對，把進度變動當新訊息。
要修：
1. 同一位置的同一則訊息正文變動 → 就地更新，不新增。
2. 生圖進度／串流中狀態文字不入庫；等穩定（圖片出現或進度消失）才寫。
3. 升級遷移：已存的重複塊，按同一對話、同位置、相鄰、只差進度文字的合併（保留最終版與圖片紀錄）。
4. 進度變動本身不算「觀察到新訊息」；穩定寫入時才更新 lastActivity（＝剛剛），不得寫出錯誤時間。
驗收：fixture 覆蓋生圖進度（頂層／iframe／shadow），只留一則；遷移測試覆蓋已存重複；1.6.4 的「剛剛」行為不回退。
