# Chatseek 功能現況與下一階段（2026-10-08）

依據：`punkcanyang/chatseek` main `806acea`（v1.2.1）的程式碼、`notes/CHANGELOG-1.1.0／1.2.0／1.2.1.md`、`notes/HANDOFF-gemini.md`、`notes/HANDOFF-bd.md`，以及規格卡 `/workspace/saas-scout/chat-search-what.md`（2026-09-14）。今天在 806acea 上重跑四組自動測試，全部通過。

## 一、目前功能

**收錄**
- 支援四家：ChatGPT（chatgpt.com、chat.openai.com）、Claude（claude.ai）、Grok（grok.com、www.grok.com、grok.x.com、x.ai）、Gemini（gemini.google.com）。
- 只讀分頁裡已經畫出來的內容，包括側欄的對話列表（標題、順序、頁面上的時間）和目前打開的那段對話正文（使用者和 AI 兩邊都收）。
- 頁面一有變動就收：MutationObserver 加 0.8 秒防抖，每 1.2 秒檢查一次網址，換頁時跟著重收；寫入失敗會自動重試。
- 不收的頁面：ChatGPT 臨時聊天（`temporary-chat=true`）、Gemini 的 `/share/`、沒有 id 的 `/app`、Gem 編輯頁，以及 `/app/download` 這類設定頁。
- Gemini 多帳號網址會保留 `/u/N/`，點回去開的是同一個帳號。
- 置頂對話不參與日期推估。

**儲存**
- 資料放在瀏覽器的 IndexedDB（資料庫 `chatseek` v2），分成對話、訊息、倒排索引、健康狀態四個 store。
- 重新載入擴充功能不會清掉資料；1.0.x 的舊資料升級到 v2 有測試涵蓋。
- 側欄有「清除本地索引」，一鍵刪光。

**搜尋**
- 標題和正文一起搜。英文和數字是完整詞比對（`music` 不會中 `musicmap`），中文用單字加相鄰雙字建索引。多個詞要出現在同一段對話裡才算命中，標題另外做子字串比對。
- 可以篩選「全部」或單一平台。結果依最後活動時間排序，最多列 80 筆。
- 點結果時，已經開著的分頁直接切過去，沒開的就開新分頁。
- 中文輸入法組字期間不會搜尋。介面語言跟著瀏覽器，有簡體、繁體、英文三種。

**日期（四家共用 `src/activity-time.js`）**
- 時間來源可信度由高到低：頁面確切時間／看到新訊息 > 側欄分組 > 側欄順序推估 > 只有收錄時間。低可信度的時間不會蓋掉高的。
- 側欄顯示四種寫法：確切時間照常顯示（例如「剛剛」「25 分鐘前」）；推估的寫成「早於 YYYY-MM-DD HH:mm」，這個時間不會隨時間漂移；分組時間寫成「約 YYYY-MM-DD」；推不出來的寫成「日期未知（收錄於 …）」。
- 在開著的分頁裡送出新訊息，那段對話會變成「剛剛」並跳到最上面。這個功能 1.1.0 其實沒生效，1.2.0 才修好。

**健康檢查**
- 對話頁大約 8 秒都讀到 0 則訊息時，側欄底部會出現「頁面可能改版」，工具列圖示顯示「!」。
- Console 只印選擇器名稱和數量，不印對話內容。

**安全邊界**
- 權限只開上面列的 8 個網域，外加 `sidePanel`。
- `npm run verify` 會擋掉 `fetch(`、XHR、`sendBeacon`、WebSocket、EventSource、`batchexecute`、`<all_urls>`、`*.google.com`。
- 不要求 API Key，也沒有任何網路請求。

**外觀**
- 圖示採用方向 D 的符文（綠 #3DDC97 配 #0B1220）。README 今天改版成同一套風格，目前只在本地分支。

## 三、已知限制

- 沒打開過、也沒出現在網站側欄的舊對話搜不到，目前也還不能匯入官方匯出檔。
- 長對話只收已經畫在頁面上的訊息，想多收就要往上捲。
- Gemini 頁面上沒有時間，沒在開著的分頁裡送過新訊息的對話，大多只能顯示「日期未知」。
- 網站一改版就可能收不到。健康檢查只抓得到「對話頁 0 則訊息」，選擇器還是要靠改版本修。
- 如果對話後來在手機上續聊、這個分頁沒看到，「早於」可能偏早。1.2.0 留下的推估列，要等該站側欄重掃一次，才會從「日期未知」變成「早於」。
- 「This month」和月份分組會被解析到今天或當月 15 日附近，顯示成「約 …」。
- 小瑕疵：簡體介面底部健康列寫「2 則消息」，計數列寫「2 條消息」，量詞不一致。
- 還沒上架 Chrome Web Store，只能用「載入未封裝項目」安裝；也還沒有收費。

## 四、下一階段建議（依優先順序）

### 1. 老闆實機驗收四家（1.2.1）
- **為什麼**：1.1.0 之後的收錄改動、1.2.0 的「看到新訊息」修正，都還沒在真頁面跑過；Claude 和 Gemini 更是一次都沒驗。規格卡寫的驗法是「搜一句上週說過的話，7 天內找不回就停」，所以這步不過，後面上架、收費都無從談起。
- **多大工**：老闆照步驟測約 30 分鐘。Gemini 最可能要再修一輪，預估 0.5～1 天開發加 Opus 複審。
- **花錢**：$0。開發照現在的方式走 Cursor 雲端（Grok Build 額度今天已經用完）。

### 2. 改版快修流程：補 Claude／Grok 離線樣本、加「複製診斷」
- **為什麼**：規格卡說得很清楚，月費賣的就是「網頁改了有人跟」。目前只有 ChatGPT 和 Gemini 有 fixture，Claude、Grok 一改版只能靠老闆回報。做法：
  - 實機驗收時存下各家去識別化的頁面結構，當成 fixture 加進測試。
  - 健康提示旁加一個「複製診斷」按鈕，把現在要老闆去 Console 抄的那一行做成一鍵複製。
  - 整理出固定流程：收到回報 → 補 fixture → 修選擇器 → 發版。
- **多大工**：1～1.5 天，要接在第 1 條之後做，因為需要真頁面的結構。
- **花錢**：$0。

### 3. 上架 Chrome Web Store 的前置作業（準備好，先不花錢）
- **為什麼**：不上架的話，一般使用者只能用開發者模式安裝，收費也就無從談起。不過規格卡定的是「自己用一週、搜得到，再報老闆怎麼收、收多少」，所以這條排在驗收之後。
- **要做的事**：
  - 隱私權政策。內容很單純，因為資料不離開瀏覽器，可以放在 GitHub Pages 或 repo。
  - 商店截圖（1280×800），可以沿用今天側欄截圖的做法，用示範資料拍。
  - 簡短描述，以及 8 個網域權限各自的用途說明。
  - 128px 圖示已經有了。
- **多大工**：約 1 天。
- **花錢**：開發者帳號一次 **US$5**，要老闆批准，批了才註冊。定價規格卡寫「先不定」，等自用一週後再報。

**暫時不排**：匯入官方匯出檔。這是解決「沒打開過的舊對話搜不到」的唯一路線，但四家格式都不一樣，工不小，等驗收和自用一週確認真的卡在這裡再開。匯出功能目前沒有使用需求，不建議做。
